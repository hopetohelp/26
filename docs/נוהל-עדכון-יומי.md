- **הקפאת קוד: 22.10.2026 בערב.** מאז — רק עדכוני נתונים לפי הנוהל, ותיקון חירום.

## הצעדים
1. **ענף חדש** מ-`main`: `claude/polls-YYYY-MM-DD`.
2. **הורדת טבלאות הסקרים** מוויקיפדיה האנגלית (טקסט המקור, `action=raw`) אל `raw/wikipedia/` — אותם שמות קבצים, דורסים את הישנים. בדף 2026 בלבד בדרך כלל.
3. **בניית הנתונים:** `python3 pipeline/build_data.py`. הסקריפט נכשל אם מנוע המנדטים לא משחזר את התוצאות הרשמיות.
4. **סקרים חדשים** = רשומות ב-`src/data/polls.json` שלא היו בגרסה הקודמת (`git diff`). לכל אחד:
   - לפתוח את הקישור לפרסום המקורי (שדה `urls`) ולהשוות: מכון, מזמין, תאריך, מדגם, **והמנדטים של כל רשימה**.
   - התאמה מלאה ⇐ להוסיף רשומה ל-`raw/verification.json` עם `status: "match"`.
   - אי-התאמה ⇐ **לא לתקן את ויקיפדיה ולא לנחש**: לרשום `status: "mismatch"` עם הפירוט; הסקר יוצג בארכיון בלי סימון "אומת".
5. **בדיקות:** `npx tsc --noEmit -p tsconfig.json && npm test && python3 pipeline/test_freeze.py && npm run build`.
6. **PR** עם רשימת הסקרים החדשים, ולכל אחד: קישור לפרסום המקורי ותוצאת ההשוואה.
7. **מיזוג** כשה-CI ירוק. סקירה של הסוכן השני (קודקס או קלוד) — כשהוא זמין; **רשומה חריגה** (מזיזה את החציון של רשימה ב-3 מנדטים ומעלה, או מכון חדש) — ב-PR נפרד, וממתינה לסקירה.
8. **אחרי המיזוג:** הפרסום ל-GitHub Pages רץ לבד. לבדוק שהאתר החי מציג "הנתונים נכונים ל-" של היום.

## מה אסור בנוהל
- לשנות קוד, עיצוב או את מנוע המנדטים — רק `raw/` ו-`src/data/` (ו-`raw/verification.json`).
- לקלוט סקר שפורסם לראשונה מתום יום שישי 23.10 ועד סגירת הקלפיות — הצינור דוחה אותו ממילא, וגם ידנית אסור.
- למחוק סקר שכבר פורסם באתר. טעות ⇐ תיקון עם הסבר ב-PR, וההיסטוריה נשארת ב-git.
