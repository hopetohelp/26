# נוהל עדכון הסקרים — בקרה יומית

**הכרעת בעלים (9.10.2026) — מחליפה את כל הכללים שלהלן שסותרים אותה:** האתר מרכז פרסומים קיימים של סקרים. כל סקר שמופיע בנתוני המקור נכנס **אוטומטית** (רענון מוויקיפדיה כל 4 שעות ב-`pages.yml`) לכל החישובים והתצוגות, **בלי תנאי אימות, בלי המתנה ובלי הגבלת תאריך**. האימות מול הפרסום המקורי הוא תווית שקיפות בלבד ("אומת"/"לא אומת"). הבעלים קיבל אישור משפטי שקליטת סקרים ופרסומם מותרים עד הרגע האחרון — אין הקפאה ואין באנר "לא עדכני". הריצה היומית היא בקרה: להוריד את העדכון לריפו (כדי שהנתונים שבריפו יהיו זהים לאתר), להוסיף שמות בעברית למכונים חדשים, וליצור תוויות אימות — אך שום סקר לא מחכה לכך.

**אושר בידי הבעלים (5.10.2026):** עדכון הסקרים עד 23.10.2026 ממוזג **בלי אישור נפרד לכל עדכון**, כל עוד הוא מבוצע **בדיוק** לפי הנוהל הזה. כל סטייה מהנוהל — חוזרת לאישור הבעלים.

**הכרעת בעלים (8.10.2026):** סקר שכבר פורסם לציבור מוצג מיד עם קליטתו, ללא המתנה של 24 שעות. הכלל חל גם על הארכיון וגם על הניתוח והמודלים.

## מתי
- בקרה פעם ביום, אחרי מהדורות הערב (סקרי הטלוויזיה מתפרסמים בדרך כלל בין 19:00 ל-21:00).
- **אין הקפאת קוד** (הכרעת בעלים 6.10.2026) **ואין הגבלת קליטה** (הכרעת בעלים 9.10.2026).

## הצעדים
1. **ענף חדש** מ-`main`: `claude/polls-YYYY-MM-DD`.
2. **הורדת טבלאות הסקרים** מוויקיפדיה האנגלית (טקסט המקור, `action=raw`) אל `raw/wikipedia/` — אותם שמות קבצים, דורסים את הישנים. בדף 2026 בלבד בדרך כלל.
3. **בניית הנתונים:** `python3 pipeline/build_data.py`. הסקריפט נכשל אם מנוע המנדטים לא משחזר את התוצאות הרשמיות.
   - הסקריפט מדפיס **"⚠️ שמות בלי תרגום לעברית"** ⇐ מכון או גוף מזמין חדש שמופיע באנגלית. להוסיף את שמו בעברית ל-`FIRM_HE` או ל-`PUB_HE` ב-`pipeline/build_data.py` באותו PR (בלעדיו בדיקות האתר נכשלות). זה החריג היחיד לאיסור שינוי קוד בנוהל, והוא מוגבל לשתי הטבלאות האלה; מכון חדש הוא ממילא "רשומה חריגה" (צעד 7).
   - שורת תוצאות בחירות או מדגם קלפיות בטבלת הסקרים אינה נכנסת כסקר — הצינור מסנן אותה לבד.
4. **סקרים חדשים** = רשומות ב-`src/data/polls.json` שלא היו בגרסה הקודמת (`git diff`). לכל אחד:
   - לפתוח את הקישור לפרסום המקורי (שדה `urls`) ולהשוות: מכון, מזמין, תאריך, מדגם, **והמנדטים של כל רשימה**.
   - התאמה מלאה ⇐ להוסיף רשומה ל-`raw/verification.json` עם `status: "match"`.
   - המקור הראשוני חוסם סריקה (ערוץ 12/mako, ישראל היום וכו'), או שהקישור שבוויקיפדיה שגוי ⇐ לא מנסים לעקוף את החסימה; מחפשים דיווח עצמאי באתר שמתיר גלישה רגילה (וואלה, כיפה, מעריב...) ומשווים את **מנדטי כל הרשימות** והסכום (120, והגושים). הכול זהה ⇐ `status: "secondary"` עם הקישור והסבר מה לא אומת (מכון, מדגם, אחוזים). רק כך הסקר נכנס לממוצע, כי הממוצע כולל רק סקרים מאומתים. לא נמצא דיווח עצמאי ⇐ `unreachable` והסקר מוצג בארכיון בלבד.
   - אי-התאמה ⇐ **לא לתקן את ויקיפדיה ולא לנחש**: לרשום `status: "mismatch"` עם הפירוט; הסקר יוצג בארכיון בלי סימון "אומת".
5. **בדיקות:** `npx tsc --noEmit -p tsconfig.json && npm test && python3 pipeline/test_model.py && npm run build`.
   - הבנייה מריצה גם את המודל והתרחישים (`src/data/model.json`) — זה חלק רגיל מהעדכון. **אין** להריץ את `pipeline/backtest.py` בנוהל: בדיקת העבר משתנה רק כשקוד המודל משתנה, וזה אינו חלק מהנוהל.
   - ב-PR לציין את השינוי הבולט בתרחישים (למשל רשימה ששיעור המעבר שלה בתרחישים זז ב-15 נקודות ומעלה).
6. **PR** עם רשימת הסקרים החדשים, ולכל אחד: קישור לפרסום המקורי ותוצאת ההשוואה.
7. **מיזוג** כשה-CI ירוק. סקירה של הסוכן השני (קודקס או קלוד) — כשהוא זמין; **רשומה חריגה** (מזיזה את החציון של רשימה ב-3 מנדטים ומעלה, או מכון חדש) — ב-PR נפרד, וממתינה לסקירה.
8. **אחרי המיזוג:** הפרסום ל-GitHub Pages רץ לבד. לבדוק שהאתר החי מציג "הנתונים נכונים ל-" של היום.

## מה אסור בנוהל
- לשנות קוד, עיצוב או את מנוע המנדטים — רק `raw/` ו-`src/data/` (ו-`raw/verification.json`). חריג יחיד: שם בעברית למכון או לגוף מזמין חדש (צעד 3).
- לגעת בדפי הסקרים של המערכות הקודמות (2019–2022) או ב-`src/data/history.json` — הם נתונים סגורים, ואינם חלק מהעדכון היומי.
- למחוק סקר שכבר פורסם באתר. טעות ⇐ תיקון עם הסבר ב-PR, וההיסטוריה נשארת ב-git.
