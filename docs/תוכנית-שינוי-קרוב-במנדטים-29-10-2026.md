# תוכנית: השינוי הקרוב במנדטים של כל רשימה (29.10.2026)

בקשת הבעלים: לכל מפלגה — כמה קולות חסרים לשינוי במנדטים, לפי חוק המנדטים (באדר-עופר והסכמי עודפים), בקולות ובאחוז ביחס למה שיש לה. ירוק לעולה, אדום ליורד. העיצוב מתואם עם הסשן השני.

## 1. החישוב (מנוע)
1. **הבעיה/הפעולה:** לכל רשימה למצוא את מספר הקולות הקטן ביותר שמוסיף לה מנדט, ואת הקטן ביותר שמוריד לה מנדט.
2. **מה בוצע:** `src/engine/seatChange.ts` — חיפוש על מנוע החוק הקיים (`allocate`), בלי חישוב משני. הקולות נוספים או נגרעים מהרשימה בלבד, והקולות הכשרים משתנים בהתאם. חלוקה שמחייבת הגרלה אינה נספרת כשינוי. בדיקות ב-`seatChange.test.ts` (2022 ו-2026): בדיוק ברף המנדטים משתנים, וקול אחד פחות אינו משנה; ההסכמה עם `votesToNextSeat`.
3. **ממתין לביצוע:** אין.
4. **נדחה:** אין.

## 2. נתוני 2026
1. **הבעיה/הפעולה:** החישוב צריך את סך הקולות הכשרים המדויק, שלא נשמר בקובץ התוצאות.
2. **מה בוצע:** השדה `valid` נוסף ל-`raw/results-2026.json` (5,320,404 — סכום הכשרים בקובץ הקלפיות), וצינור העדכון (`pipeline/fetch_results_2026.py`) כותב אותו בכל עדכון. `seatChanges2026()` ב-`src/lib/guessAccuracyData.ts` מחזיר null כשהשדה חסר.
3. **ממתין לביצוע:** לבדוק בריצת העדכון הראשונה אחרי המיזוג שהשדה נכתב.
4. **נדחה:** אין.

## 3. תצוגה
1. **הבעיה/הפעולה:** להציג את השינוי הקרוב לכל רשימה, ירוק לעולה ואדום ליורד, בקולות ובאחוז ביחס לקולות שיש לה.
2. **מה בוצע:** עמודה "השינוי הקרוב במנדטים" בטבלת 2026 במסך "תוצאות אמת" (תצוגה מורחבת), מהטוקנים `pos` ו-`neg`, עם חץ וסימן (לא צבע בלבד), הסבר צמוד וערך במילון (`seat-change`). נבדק בטלפון ובמחשב, ביום ובלילה, בלי גלילה אופקית.
3. **ממתין לביצוע:** עיצוב סופי ומיקום במסך הראשי "תוצאות אמת" — בתיאום עם הסשן השני; בטלפון השורות צפופות. בדיקה באתר החי אחרי מיזוג ופרסום.
4. **נדחה:** הצגה בבחירות קודמות (2015–2022) — הנתונים קיימים, ממתין להחלטת הבעלים.
